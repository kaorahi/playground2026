遊び方

どうぶつしょうぎのルール

  • 各駒はマークの方向に一歩動けます。
  • 相手のライオンを取れば勝ちです。（キャッチ）
  • 自分のライオンを相手側の一番奥の段まで進めて、相手の次の手で取られなければ、それも勝ちです。（トライ）
  • ひよこは相手側の一番奥の段まで進むと、にわとりに成ります。

このページの遊び方

  • 詰将棋の問題が自動生成されます。駒を動かして、指定の手数で勝ってください。
  • あなたは先手です。手前から奥へ（画面の下から上へ）攻める側です。
  • 詰将棋モードでは王手（またはトライをうかがう手）しか指せません。自由手モードでは王手以外も指せます。
  • 答ボタンを押すと正解の駒に赤丸がつきます。その駒を動かすと正解の移動先に赤丸が出ます。緑×は不正解だった手です。答を隠すボタンで通常表示に戻ります。
  • ボタンでその問題が好きか嫌いかを入力すれば、あなたの好きそうな問題が出やすくなります。

おまけ

  • 戻る進むボタンは長押しで最初・最後へ飛べます。

0. 大枠

    
    
    
  • 候補局面を多数用意
    • 
    
  • 問題として成立しているものを抽出
    • 
    
  • 各問題の特徴量を計算
    • 
    
  • 特徴量から問題の良さを評価
    • 
    
  • 提示する問題を選択
    • 
    

    

    

    
1. 候補局面の作り方

    
事前解析データを使わない場合は、駒の配置と所属を次の確率で無作為に決め、先手番の候補局面を作ります。

    
    
    
  • 後手ライオンは上2段、先手ライオンは下2段の空きマスから等確率で配置する。
    • 
    
  • 残り6枚（きりん2、ぞう2、ひよこ2）は、1枚ごとに先手40%・後手60%で所属を決める。
    • 
    
  • 各駒は74%でその側の盤上、26%で持駒にする。盤上に置く場合は空きマスから等確率で選ぶ。
    • 
    
  • 盤上のひよこは18%でにわとりにする。ただし相手陣の最終段に置かれたひよこは必ずにわとりにする。
    • 
    

    
事前解析データを使う場合は、指定手数の成立局面一覧から候補局面を無作為に選びます。最奥段に未成のひよこがある局面は除きます。

    

    

    
2. 事前チェック

    
成立探索に入る前に、候補局面が次の条件をすべて満たすことを確認します。

    
    
    
  • 開始時にどちらのライオンも王手されていない。
    • 
    
  • 先手に合法手が2手以上ある。
    • 
    

    

    

    
3. 成立チェック

    
指定手数以内に先手が必ず勝てるかを調べます。このアプリでは、自分のライオンを相手の利きに残す手を合法手から除きます。ただし相手ライオンを取る手は、その時点で勝ちなので除きません。手番側に合法手がなければ、その手番側の負けとして扱います。先手番では勝ちにつながる手が1手あればよく、後手番ではすべての応手に対して先手が勝てる必要があります。

    
指定手数より2手短い手数でも先手が必ず勝てる局面を除外します。これによって、指定手数より早く決着する問題を落とします。1手詰ではこの判定を行いません。7・9・11手詰では、この短い勝ちの除外を指定手数の判定より先に行います。

    
最後に初手を1手ずつ調べ、指定手数内の勝ちにつながる初手がちょうど1手であることを確認します。詰将棋モードでは王手・トライ・次手のトライを狙う手だけを候補にし、自由手モードでは全合法手を候補にします。

    
これらの成立チェックは共通の探索機構を使い、先の段階で得た探索結果は後の判定や特徴量計算でも再利用します。

    
なお、事前解析データから候補局面を得た場合は、指定手数以内で先手が勝てることと、2手短い手数以内では勝てないことが既知なので、この2つの確認は省きます。

    

    

    
4. 正解手順の作成

    
成立した局面では、先手が最短で勝ち、後手が最も長く抵抗する最善系列の中から1本を選び、以後これを正解手順とします。同じ手数の候補が複数ある場合、先手は相手の有力応手数が少ない手を、後手は紛らわしい候補手数が多い手を優先します。それでも同じ場合は、合法手の生成順で先の手を選びます。

    

    

    
5. 特徴量の計算

    
成立した候補を特徴量ベクトル v(p) に変換します。数値特徴は0から記載した上限までの整数値とし、その値を上限で割って0から1の特徴量に変換します。条件特徴は0または1とします。現在の実装では、特徴量は定数項も含めて32成分です。

    

    
定数項

    
常に1。上限1。標準重み−2。

    
詰手数

    
n手詰ならn−1。上限10。標準重み0。

    
別解のない局面数

    
正解手が1手だけの先手番の局面数。上限6。標準重み0.96。

    
紛らわしい候補手数

    
各先手番の候補手のうち、残り手数内で勝てない手の総数。各局面3手まで、上限18。標準重み1.44。

    
不正解の攻め手長

    
詰将棋モードで、紛らわしい候補手から許された攻めを続けられる最大手数。最初の不正解手を含め、上限3。標準重み0.24。

    
別解数

    
各先手番の正解手について、1手を除いた数の合計。各局面3手まで、上限18。標準重み−7.2。

    
正解が唯一＋紛らわしい候補手あり

    
すべての先手番で正解手が1手だけで、かつ紛らわしい候補手を含む局面があれば1。上限1。標準重み0.36。

    
相手の有力応手2手の局面数

    
有力な応手、すなわち先手勝ちを早めすぎない応手（早めても2手まで）が2手ある後手番の局面数。上限5。標準重み0.6。

    
相手の有力応手3手の局面数

    
有力な応手が3手ある後手番の局面数。上限5。標準重み1。

    
相手の有力応手4手の局面数

    
有力な応手が4手ある後手番の局面数。上限5。標準重み0.4。

    
相手の有力応手5手以上の局面数

    
有力な応手が5手以上ある後手番の局面数。上限5。標準重み−0.8。

    
詰み時のライオン周辺空きマス数

    
詰みで決着した最終局面で、後手ライオンの周囲8方向のうち、盤内で駒のないマス数（参考文献）。上限8。標準重み0.32。

    
初手が打ち駒

    
正解手順の初手が持駒を打つ手なら1。上限1。標準重み0.08。

    
トライで決着

    
正解手順の最終局面が先手のトライなら1。上限1。標準重み0。

    
先手の冗長な初期駒なし

    
ライオン以外の先手初期駒が1枚以上あり、そのどの1枚を後手持駒に渡しても指定手数以内で勝てなくなるなら1。上限1。標準重み0.2。

    
先手の冗長な初期駒数

    
ライオン以外の先手初期駒のうち、その1枚を後手持駒に渡しても指定手数以内で勝てる駒の枚数。上限6。標準重み−2.4。

    
勝ち上がりの持駒数

    
正解手順の最終局面での先手の持駒数。上限6。標準重み−1.44。

    
4枚目以降の先手初期駒数

    
初期局面の先手の非ライオン駒を盤上と持駒で数え、3枚を超えた数。上限3。標準重み−0.24。

    
指した駒が直後に取られる手

    
先手が指した駒を、直後に後手が取る場面が正解手順内にあれば1。上限1。標準重み0.32。

    
指した駒が直後にライオンに取られる手

    
先手が指した駒を、直後に後手ライオンが取る場面が正解手順内にあれば1。上限1。標準重み0.4。

    
上記＋王手

    
その先手の指手が王手なら1。上限1。標準重み0.12。

    
上記＋駒取り王手

    
その先手の指手が駒取り王手なら1。上限1。標準重み0.08。

    
上記＋ライオンを最上下段へ誘導

    
駒を取った後手ライオンが盤の最上段または最下段にいれば1。上限1。標準重み0.04。

    
上記＋次に王手

    
その次の先手の指手が王手なら1。上限1。標準重み0.12。

    
上記で駒を入手＋次に入手駒で王手

    
その先手の指手が駒取りで、その次に入手した駒を打って王手すれば1。上限1。標準重み0.12。

    
同一駒の連続使用回数

    
正解手順で、先手が同じ1枚の駒を続けて指す最大回数。後手の応手を挟んでも先手の連続使用として数えます。上限5。標準重み0。

    
連続取り返し回数

    
正解手順で、先手・後手が交互に同じマスで駒を取る最大連続回数。開始は先手からでも後手からでもよい。上限10。標準重み0。

    
詰将棋モードでは指せない手の回数

    
自由手モードで、先手が王手・トライ・トライをうかがう手のいずれでもない手を指す回数。上限5。標準重み0。

    
静かな手の回数

    
自由手モードで、先手が王手・トライ・駒取りのいずれでもない手を指す回数。上限5。標準重み0。

    
ただ取りする回数

    
先手が駒を取り、直後の後手の手でその先手駒を取り返されない回数。ただし、直前の後手の駒取りに対する取り返しと、後手の応手がない最終手は除きます。上限5。標準重み0。

    
ライオンにただ取りされる回数

    
先手が後手の駒を取らずに指した駒を、直後に後手ライオンが取る回数。上限5。標準重み0。

    
ライオン以外にただ取りされる回数

    
先手が後手の駒を取らずに指した駒を、直後に後手のライオン以外の駒が取る回数。ただし、その直後に先手がその後手駒を取り返す場合は除きます。上限5。標準重み0。

    

    
「不正解の攻め手長」「先手の冗長な初期駒なし」「先手の冗長な初期駒数」は追加探索が必要なので重い特徴量とし、それ以外を先に計算します。

    
標準評価では各特徴量に上記の標準重みを掛け、その合計を活性値とします。活性値をロジスティック関数で0から1に変換した値を、標準の推定↑率とします（高評価・低評価を↑・↓で表記）。

    

    

    
6. 好みの学習

    
成立した問題の特徴量を入力とし、↑・↓の記録から、どのような問題を好むかをモードごとに学習して問題選択に使います。

    

    
学習開始条件

    
現在のモードで↑が件以上、↓が件以上になると好みを学習します。

    
バッチ学習

    
投票が追加・変更・取消されるたびに、現在のモードで記録されているすべての↑・↓を使ってモデルを学習し直します。詰手数の異なる問題も同じモデルで学習します。

    
学習モデル

    
好みの学習にはL2正則化付きロジスティック回帰を使います。定数項は切片として扱い、それ以外の特徴量にそれぞれ係数を学習します。L2正則化係数は1で、切片は正則化しません。パラメータはHessianにもとづくNewton法で最適化し、更新にはbacktrackingを用います。投票が変わるたびに現在のモードの全記録から学習し直します。

    
推定↑率

    
切片と各入力の「係数×入力値」を足し合わせた活性値 u をロジスティック関数 y=1/(1+e^{-u}) で0から1に変換し、推定↑率とします。

    
上限評価による枝刈り

    
まず軽い特徴量だけを計算します。まだ計算していない重い特徴量は0から1の範囲で係数の符号に応じて最も有利な値を仮定し、活性値の上限を求めます。その上限でも現在の最有力候補を超えない問題は、重い特徴量の計算を省略します。

    

    

    

    
7. 問題の選択

    
問題生成では、まず持越し分を評価し、その後、新しい候補局面を順次用意して成立チェック・評価を行います。次の局面数または時間の上限に達した時点で打ち切ります。局面数は新規候補のみを数え、時間は持越し分の評価から通算します。

    
    
    
  • 1手詰：最大900局面、2.5秒。
    • 
    
  • 3手詰：最大2,200局面、4秒。
    • 
    
  • 5手詰：最大3,500局面。詰将棋モードは5.5秒、自由手モードは6秒。
    • 
    
  • 7手詰：最大5,200局面、8秒。
    • 
    
  • 9手詰：最大7,000局面、12秒。
    • 
    
  • 11手詰：最大9,000局面。詰将棋モードは16秒、自由手モードは20秒。
    • 
    

    
正解手順まで作成できた成立問題は、採用されなかった場合も持越し分としてページを開いている間は保存します。次回以降に同じモード・手数で生成するときは、まず持越し分を評価します。保存数は全モード・全手数を合わせて最大問です。上限を超えた場合は、現在と異なるモード・手数の問題を対象に、新しさ順位と評価順位の合計にもとづいて削除します（評価順位は、標準順位と好み順位の高いほう。ただし、モード・手数や詳細評価・上限評価の違いは考慮せず単純比較）。好み評価には、その問題を最後に問題選択へ通した時点の値を使います。さらに必要なら、現在のモード・手数の問題からも同じ基準で削除します。

    
「好み」「標準」「無選好」にはそれぞれ強制割当率を設定します。強制分を除いた残りは、Thompson samplingで分けます。具体的には、現在のモードの直近件の投票について、「好み」と「標準」の↑数をu、↓数をdとして、それぞれ分布 Beta(u+1, d+1) から乱数値を1つ取り、大きい側を選びます。ただし、生成時に「好み」の予測がなかった問題は、この集計には含めません。反映開始前は「好み」を「標準」として扱います。持越し分と今回新しく成立した問題を合わせ、「好み」では学習したL2ロジスティック回帰による活性値が最も高い問題を、「標準」では固定された標準評価の活性値が最も高い問題を採用します。「無選好」では、持越し分・今回新規の順に並べた候補のうち最後の問題を採用します。採用されなかった成立問題は次回以降へ持ち越します。

    

    

    
8. 探索のしくみ

    
探索の中心は、「この局面から先手が○手以内に必ず勝てるか」という問い合わせです。利用側は勝てる・勝てないという答えを受け取り、探索方法や途中結果の管理は共通の探索機構に任せます。

    
探索機構は局面ごとに、「何手以内なら勝てると分かっているか」と「何手以内では勝てないと分かっているか」をそれぞれ記録します。後で別の手数を問い合わせたとき、記録だけで答えられる場合は新たな探索をしません。記録だけでは答えられない場合に限って、答えを出すのに必要な範囲を追加探索し、記録を更新します。

    
事前解析データが与えられた場合にはそれを利用します（指定詰手数の局面一覧に加えて5手詰局面一覧も援用）。

    

    

    
9. 現在の限界

    
    
    
  • 候補局面は完全列挙せず無作為に調べるため、同じ設定でも結果は変わり、最高評価の問題を必ず見つける保証はありません。
    • 
    
  • 表示する局面自体の成立条件は検証しますが、通常のどうぶつしょうぎの初期配置からその局面へ実戦で到達できるかは確認していません。

セットアップ

       
HTMLファイル一枚で外部依存なしでも動作します。

       
探索を効率化するには、事前解析データも利用できます。データやファイル配置についてはGitHubを参照。この場合はデータの展開にxz-decompress-0.2.3を使います。

      

      

       
構成

       
最初の <script id="tsumeDobutsuCoreScript"> はアプリの中核処理を担当します（盤面、探索、作問、評価、好みモデルと TsumeDobutsuCore API）。2つ目の <script> はブラウザ上の画面と操作を担当します（画面表示、操作、ブラウザ内の保存、URL、クリップボードなど）。

       
中核処理コードはそのままコピーしてNode.jsで実行できます。現在のAPIバージョンは 3 です。

      

      

       
Node.js での実行例

       
最初の script の中身を core.js に保存し、次のコードを末尾に追加して node core.js を実行します。

       
const core = globalThis.TsumeDobutsuCore;
const position = core.parsePosition("04400419050b0a0");

const result = core.solve(position, {
  mode: "normal",
  maxMoves: 3
});

console.log(result);

メイン API

       
高評価・低評価を↑・↓で表記します。

       

        
メソッド用途

        
         
parsePosition(text)15桁hexの局面コードまたはcsa棋譜形式風の局面文字列を盤面オブジェクトに変換します（先手番用）。

         
formatPosition(position, format)盤面を "csa" または "hex" に変換します（先手番用）。

         
legalMoves(position, options)合法手一覧を返します。各手には移動後の盤面も含まれます。

         
createSearch(options)探索機構オブジェクトを作ります。同じオブジェクトで問い合わせを続けると、それまでの探索結果を再利用します。

         
solve(position, options)指定手数以内の勝ち、最短手数、主手順を調べます。options.search に探索機構オブジェクトを指定できます。

         
verifyPuzzle(position, options)指定手数の問題として成立するか、短い勝ちや初手一意性を含めて検査します。options.search を指定すると探索結果をそのオブジェクトに蓄積します。options.timeLimitMs で時間制限を指定した場合、時間切れでは timedOut: true を返します。

         
scorePuzzle(position, line, options)特徴量と標準・好みの活性値を計算します。featureVector、standardActivation、learnedActivation を返し、options.search で既存の探索結果を利用できます。

         
generatePuzzle(options)条件に合う問題を生成し、指定した評価方法で候補を選びます。生成結果は左右正規化した向きです。options.search に探索機構オブジェクトを指定できます。

         
fitPreferenceModel(ratings)↑・↓と特徴量から好みモデルを学習します。↑が件未満、または↓が件未満なら null です。

         
evaluatePreference(featureVector, model)標準・好みの活性値、推定↑率、特徴ごとの寄与を計算します。

         
evaluatePreferenceUpper(lightFeatures, model)軽量特徴量から標準・好みの活性値上限を計算します。

探索機構オブジェクト

       
createSearch() が返す探索機構オブジェクトは探索結果を保持します。canWinWithin(position, maxMoves, options)、winDistanceWithin(position, maxMoves)、principalWinLine(position, maxMoves)、bestDefenseMove(position, remaining)、clear()、stats()、setPreanalysisData(mode, moves, data) を使えます。canWinWithin は options.timeLimitMs で時間制限を指定でき、時間切れでは null を返します。同じ探索機構で再実行すると、それまでに確定した探索結果を再利用します（実質的には「続きを探索」）。時間制限付きの実行を繰り返すことにより、途中で制御を返しながら長時間の探索を進められます。別途作成した事前解析データをsetPreanalysisData で渡すと、以後の探索が効率化されます。

       
const search = core.createSearch({ mode: "normal" });

search.canWinWithin(position, 7);
search.winDistanceWithin(position, 11);
search.principalWinLine(position, 3);

const verified = core.verifyPuzzle(position, {
  moves: 3,
  search
});

const score = core.scorePuzzle(position, verified.line, {
  search
});

      

      

       
好みの記録

       
好みの記録はブラウザの localStorage にJSON形式で保存します。現在の形式バージョンは 21 です。

       
トップレベルには version、ratings、selections、forcedAllocation を保存します。

       
ratings は↑↓投票の履歴です。

       
    
        
  • i: 16桁hexの識別用ランダムid
    • 
        
  • p: 左右正規化した15桁hexの初期局面コード
    • 
        
  • m: "normal"（詰将棋モード）または "fairy"（自由手モード）
    • 
        
  • n: n手詰
    • 
        
  • v: ↑なら 1、↓なら -1
    • 
        
  • g: 選択方法。"initial"＝標準、"learned"＝好み、"none"＝無選好、""＝不明
    • 
        
  • x: 特徴量
    • 
        
  • a: 生成時点の好みの推定↑率。存在しない場合もある（読込、好みの反映前、旧データからの移行分）。
    • 
        
  • s: 生成時点の標準の推定↑率。存在しない場合もある（アルゴリズム変更時の旧データ移行分）
    • 
       

       
selections は、直近問の生成実績です（識別用ランダムid、モード、n手詰、選択方法。投票の有無は問わない。生成時に「好み」の予測がない問題は除く）。forcedAllocation は各選択方法への強制割当率の設定です。

       
ratings と selections は古い記録が前、新しい記録が後に並びます。既存の投票を変更した場合、その記録は更新時点の新しい記録として末尾へ移ります。

       
例

       
{
  "version": 21,
  "ratings": [
    {
      "i": "7c4f0a9e13d6b825",
      "p": "000b0029c41a003",
      "m": "normal",
      "n": 7,
      "v": 1,
      "g": "learned",
      "x": [1, 0.6, 0.5, 0.333333, …],
      "a": 0.61,
      "s": 0.54
    },
    …
  ],
  "selections": [
    {"i": "3a891de720c45f6b", "m": "normal", "n": 7, "g": "initial"},
    …
  ],
  "forcedAllocation": {
    "learnedShare": 10,
    "initialShare": 10,
    "noneShare": 10
  }
}

       
    
        
  • 好みモデル自体は記録しません。特徴量と↑↓を一式記録し、実行時にその場で好みモデルを作成します。これは、将来のモデル変更も想定しての仕様です。
    • 
        
  • selectionsは、「好みの反映状況」の「生成内訳」欄の集計用です。問題生成や好みモデルの学習には使われません。
    • 
        
  • 好みの記録を取り込むと、現在の記録の後に取込側の記録を追加します。同じidの記録は重複して追加しません。ratings で同じ問題のidが異なる場合は、取込側を新しい記録として採用します。forcedAllocation は現在の設定を維持します。
    • 
       

      

      

       
短縮局面コード

       
手入力用の短縮局面コードも使えます（jovz0mpgh のような9文字）。

       
    
        
  • チェックデジット：中央の1桁。数字を除く8文字について、文字コード×位置番号（1〜8）の総和の下1桁
    • 
        
  • 駒：ライオン、ゾウ、キリン、ひよこ系の順に2文字ずつ
    • 
        
  • 位置：a〜l＝先手の盤上12マス、m＝先手の持駒、n〜y＝後手の盤上12マス、z＝後手の持駒。盤上は上段左から順（abcが最上段）
    • 
        
  • 並び：同種の2文字は文字コード順
    • 
        
  • ライオンとにわとり：1文字目＝先手ライオン、2文字目＝後手ライオン。a〜l / n〜y で位置を表し、n〜y なら対応するひよこ系の駒はにわとり
    • 
       

       
「盤面コピー」の貼付欄は、15桁hex・局面文字列・URLおよびこの短縮局面コードを受け付けます。
