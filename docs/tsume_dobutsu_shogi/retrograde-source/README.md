# 詰めどうぶつしょうぎ：全局面後退解析と手数別データ

この一式は、標準の初期配置から到達できる局面を列挙し、詰将棋モード (`normal`) と自由手モード (`fairy`) について、指定した手数、または全手数で攻め側が勝ちを強制できる局面をそれぞれ `normal-5.bin.xz` などの名前で出力します。

## 実行

Linux x86-64、Rust 1.98.1 で確認済みの `rustc`、Python 3、GNU Make、`xz`、`sort`、`bash` が必要です。メモリは約10 GiB、作業用ディスクには余裕を持たせてください。モード間の並列実行（`make -j`）は避けてください。

```sh
make normal-11.bin.xz   # Normal mode through 11, exporting 1, 3, ..., 11
make fairy-13.bin.xz    # Fairy mode through 13, exporting 1, 3, ..., 13
make normal-all         # Normal mode until convergence
make fairy-all          # Fairy mode until convergence
make verify             # Validate every existing binary output
```

引数なしの `make` は両モードの11手までを実行します。指定手数は正の奇数です。同じモードの次の手数を実行すると保存済みの層から再開します。`*-all` は新規確定局面がゼロの層まで進み、出現した奇数手のファイルをすべて作成します。指定手数より前に収束したときは、残りの指定手数のファイルは空の配列として作成します。コマンドを繰り返した場合、既存の出力ファイルは再生成しません。

`data/reachable_1.txt.xz` は共通の全到達局面、`build/{normal,fairy}-layers/depthNN.txt.xz` は完成済みの層です。各層の保存はファイルの置換で確定し、中断時の `*.pending` は使いません。再開には全到達局面と保存済みの層を読み直す時間がかかります。標準エラーには再開時間、各層の件数・秒数、直近の層の縮小率に基づく残り時間の概算を出します。この概算は層の縮小率が変わると大きく外れます。ルールやキー形式を変更した後は `make clean` からやり直してください。

## 出力の定義

`{normal,fairy}-{odd_depth}.bin.xz` の各ファイルには、**そのモードで、攻め側手番から最短の強制勝ちまでがちょうど指定手数**の局面だけが入ります。攻め側は固定した先手（side 0）。初手の一意性や、アプリの問題生成時の開始局面フィルタは課していません。ここでいう勝ちは相手ライオンの捕獲、安全なトライ、または守り側の基本合法手ゼロによる勝ちを含みます。

`xz` を展開した内容は、**uint64 little-endian を数値の昇順に並べた配列**です。1局面8バイトで、重複・ヘッダ・件数・手数・区切り文字はありません。件数は展開後のバイト数を8で割った値です。先頭60ビットが局面キー（15桁hex相当）で、上位4ビットは0です。xz ファイルには圧縮形式のヘッダがありますが、展開後の配列には独自ヘッダはありません。

局面キーの盤上48ビットは、各マスを4ビットで表します。アプリの盤面を上から `row=0..3`、左から `col=0..2` とすると、マスの nibble 番号は `(2-col)*4 + (3-row)` です。コードは `0` 空、先手の `1=L, 2=E, 3=G, 4=C, 5=H`、後手はそれぞれ `9..13`。持駒は bit 48 から先手の E/G/C 各2ビット、bit 54 から後手の E/G/C 各2ビットです。盤面を左右反転したキーとの小さい方に正規化します。中間ファイルだけは bit 60 に手番を持ち、出力には先手手番 (bit 60 = 0) の局面だけを入れます。

## master (`val1n`) とのルール差分

* [master](https://github.com/kaorahi/dobutsu-shogi-master)
* [この実装（tsume）](https://github.com/kaorahi/playground2026/tree/main/docs/tsume_dobutsu_shogi)

| 項目 | master | この実装（tsume） |
|---|---|---|
| 駒・持駒 | 標準 `val1n`。駒の動きとトライ有無は master の `RULES` で変更可能 | 標準の動き・成り・持駒に固定。標準 `val1n` の到達局面では駒の動かし方は一致 |
| 基本指手 | 自分のライオンが取られ得るままの指手も生成 | 指した後に自分のライオンが攻撃される手は除外。ただし相手ライオンを直ちに取る手は許す |
| 攻め手 | 追加制限なし | `fairy` は基本合法手の全手。`normal` は先手の手を「王手／安全なトライ／相手がパスしたと仮定すれば次手に安全なトライが可能」のいずれかに限定。後手は両モードとも基本合法手の全手 |
| ライオン取り | 手番側が次の一手で取れる局面を即勝ちとし、取り終えた局面は生成しない | 捕獲する指手を生成し、相手ライオンが消えた局面を勝ちの深さ0とする |
| トライ | まず手番側の相手ライオン即取りを判定し、その後で相手ライオンが自陣最奥段にいれば手番側を負けとする | 敵陣最奥段にいて相手の駒から攻撃されていないライオンの持ち主を勝ちとする。判定順は先手の捕獲・安全なトライ、後手の捕獲・安全なトライ、基本合法手ゼロ。勝利条件が同時に見える局面では優先順位によって差が出る |
| 基本合法手ゼロ | 他の即決着条件がなければ未確定とし、最終的に引分 | 手番側の負け。先手番なら先手負け、後手番なら先手勝ち |
| `normal` で許された先手だけがゼロ | 該当する制限なし | 基本合法手が残る場合は即時の終局にはせず、先手の強制勝ちなしとする |
| 循環と勝敗 | 双方の勝敗・引分を解く。循環は引分 | 固定先手が指定手数までに勝ちを強制できるかを解く。循環、先手負け、解析した深さを超える勝ちは出力対象外 |

master は手番側へ盤面を入れ替えて符号化しますが、こちらは先手を固定して手番を別の1ビットで持ちます。したがって master のキーや深さをそのまま流用できません。なお、出力に「詰み」と名付けていますが、守り側の合法手ゼロには王手されていない局面も含みます。

## 実測結果（両モードとも最大11手）

初期局面からの共通の全到達局面は **213,009,106件**（両手番を含む）。うち先手手番は **106,504,553件**です。`data/reachable_1.txt.xz` は約852 MiBでした。11手以内に先手勝ちが確定した局面（両手番・深さ0や偶数深さを含む）は `normal` **51,454,362件**、`fairy` **79,479,750件**。全到達局面との差はそれぞれ **161,554,744件**、**133,529,356件**で、負け・引分と11手を超える勝ちなどが混在します。

## ソース構成

- `src/tsume-sample.rs`: 固定先手から見た盤面・合法手・決着・水平反転の正規化。
- `src/tsume-enum.rs`: 初期配置から全到達局面を1回列挙。
- `src/tsume-reverse.rs`: 前駆局面の候補生成と、正方向の合法手との照合。
- `src/tsume-analyze-checkpoint.rs`: モード別の後退解析、深さごとの xz チェックポイントと中断再開。
- `run_analysis.py`: 手数指定・全手数実行と再開、手数別ファイルの作成。
- `export_depth.py`: 指定手数・先手手番のキーだけを選び、絶対値でソートして xz 化。
- `verify_outputs.py`: 展開した配列の構造・範囲・昇順を確認。
- `Makefile`: 初期局面から最終12ファイルまでの実行順序。
